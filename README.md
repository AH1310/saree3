# سريع — حزمة النشر

حزمة الموقع مبنية على ملف HTML المرسل، مع الحفاظ على تدفق الخدمات والحسابات ومعرض الأعمال، وإضافة هوية سريع، إعادة تصميم القائمة والبطاقات مع الحفاظ على الألوان، ونقل رابط AH13 إلى القائمة، نموذج الشكاوى والاقتراحات، إدارة الشكاوى والإشعارات، محادثات نصية بين المستخدمين، ودعم PWA. المنصة لا تخصم عمولة حاليًا ولا تتضمن دفعًا داخل الموقع.

## قبل النشر

1. في Supabase افتح **SQL Editor** وشغّل الملف `supabase/setup.sql`.
2. في **Authentication → Sign In / Providers → Email** اترك Email مفعّلًا وأوقف **Confirm email** كما طلبت.
3. تأكد أن حسابك مسجل في المشروع الجديد، وأن UID الظاهر في **Authentication → Users** يطابق معرّف الإدارة المذكور داخل SQL. شغّل كتلة منح الأدمن الموجودة آخر SQL بعد وجود المستخدم. إذا كان UID مختلفًا، عدّل قيمة UID في آخر SQL وكذلك في `app-enhancements.js` لتطابقه. الحساب لا يحصل على الإدارة إلا إذا طابق UID والبريد معًا.
4. في **Authentication → URL Configuration** أضف رابط الموقع المنشور إلى Site URL وRedirect URLs.
5. ارفع محتويات هذا المجلد إلى استضافة HTTPS. PWA والتخزين المؤقت يحتاجان HTTPS (أو localhost). بعد فتح الموقع مرة يظهر خيار التثبيت من المتصفح.

## ملف إبقاء Supabase نشطًا

المجلد `.github/workflows/supabase-activity.yml` يرسل طلب قاعدة بيانات خفيفًا مرة يوميًا كأفضل محاولة لمشروع Free. بعد رفعه إلى مستودع GitHub، أضف في إعدادات المستودع **Settings → Secrets and variables → Actions → New repository secret** القيمتين: `SUPABASE_URL` و`SUPABASE_PUBLISHABLE_KEY`.

هذا الفحص قد يساعد في إظهار نشاط، لكنه **لا يضمن منع الإيقاف**؛ Supabase يوضح أن المشاريع المجانية منخفضة النشاط قد تُوقف بعد أسبوع، وأن طلبات فعلية يومية قد تساعد دون ضمان. الخطة المدفوعة تمنع الإيقاف التلقائي بسبب الخمول. لا يستطيع PWA نفسه إبقاء قاعدة البيانات مستيقظة.

## ما في النسخة

- تسجيل ودخول بالبريد وكلمة المرور، وتأكيد كلمة مرور عند التسجيل. الجلسة تحفظ محليًا في المتصفح عبر Supabase Auth.
- خدمات البائعين ومعرض الأعمال والتواصل عبر واتساب أو محادثة نصية داخل الموقع.
- لوحة الأدمن تميّز الخدمة سبعة أيام وتسمح بإلغاء التمييز؛ النشر يظل مباشرًا دون مراجعة مسبقة.
- صفحة **الشكاوى واقتراحات تطوير للموقع**: الاسم والهاتف والبريد اختيارية، والعنوان والتفاصيل مطلوبة.
- لوحة الإدارة تظهر للحساب المطابق للبريد وUID فقط، وتتيح مراجعة الرسائل وتغيير حالتها ونشر إشعارات عامة أو لمعرفات مستخدمين محددة. سياسات RLS تتحقق من صلاحية الأدمن في قاعدة البيانات أيضًا.
- نشر الخدمات لا ينتظر موافقة أدمن.
- صندوق رسائل خاص بين العميل ومقدم الخدمة، واستطلاع للرسائل كل 10 ثوانٍ أثناء فتح المحادثة.
- Manifest وService Worker وoffline.html وملفات الأيقونة، مع عدم تخزين استجابات Supabase الخاصة في cache.

لا يحتوي هذا الإصدار على مراجعات/دفع/رسائل داخلية أو أنظمة نزاع؛ تلك ميزات تحتاج تصميم جداول وتدفقات إضافية قبل اعتبارها جاهزة للإنتاج.
